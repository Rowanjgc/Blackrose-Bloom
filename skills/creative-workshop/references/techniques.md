# Creative Workshop techniques

Use one technique when it helps. None is a required procedure.

## Divergence methods

- **Change the axis:** vary one fundamental dimension per option: point of view,
  time scale, genre, stakes, mechanism, audience or material.
- **Invert an assumption:** list what the premise takes for granted, then flip
  one. A heist where the thieves return something; a calendar app that hides
  most of your week.
- **Combine distant domains:** borrow a structure from an unrelated field, such
  as a mystery structured like a recipe, or navigation modeled on a library's
  shelving.
- **Follow consequences:** take the premise's central rule and ask what it would
  do to daily life, economics, relationships or failure cases.
- **Specificity pass:** replace each generic noun with a particular one. "A
  city" becomes "a salt-mining town that rations fresh water by the hour".

Test a set of options by asking whether a reader could tell them apart from a
one-line summary. If not, they differ only cosmetically.

## Productive constraints

| Constraint | What it is for |
| --- | --- |
| Single location or short time span | Concentrates pressure; forces invention within limits |
| Limited palette, material or type set | Coherent identity; decisions become visible |
| A rule the world must obey, with a cost | Makes worldbuilding generate plot rather than decoration |
| Formal restriction (second person, letters, one-sentence scenes) | Breaks habitual voice |
| One core interaction or verb | Clarifies a game or product's center |
| Remove the obvious solution | Forces a less conventional approach |

Offer a constraint with its purpose, and drop it if it does not serve the work.

## Development moves by medium

**Fiction:** for each main character, a want, a need that conflicts with it, and
a choice that reveals them. Outline turning points rather than events. Write a
sample scene to test voice before planning everything.

**Worldbuilding:** start from rules that affect characters, not from encyclopedic
history. For each rule, name who benefits, who pays, and what breaks it. Leave
deliberate unknowns.

**Visual and product design:** state the feeling and the job before style.
Develop a key screen, object or layout in detail, then the system around it.
Check hierarchy, contrast, accessibility and the moments where the user is
uncertain.

**Interaction and game concepts:** define the core loop, what the player or user
decides, what feedback they get, and how difficulty or depth grows. Prototype on
paper or as a short written walkthrough before elaborating.

**Personal projects:** connect the work to why the person is making it, and to
the time, skills and materials they have. Suggest a first small piece they can
finish.

## Critique methods

- **Intent check:** state what the work seems to be trying to do. If that
  differs from the user's intent, that gap is the first finding.
- **Effect over rule:** describe the effect a choice has on the reader or user
  ("the reveal lands before we care about her"), not a generic rule ("show,
  don't tell").
- **Most leverage first:** two or three changes that matter beat twenty notes.
- **Alternatives, not verdicts:** for each issue, sketch two possible
  directions and what each would emphasize.
- **Protect the strange:** name the distinctive choices that should survive
  revision, so fixes do not erase them.
