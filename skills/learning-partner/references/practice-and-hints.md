# Practice, hints and transfer

Use this when the user wants to practice, check understanding or apply an idea to
something new. Keep it optional: offer, do not insist.

## Choosing a practice problem

- Aim just beyond the worked example: same idea, one new wrinkle.
- Prefer problems whose answer can be checked: a number, a prediction, a working
  snippet, a diagram the user can compare.
- Keep one problem at a time unless the user asks for a set.
- Use the user's own domain when you know it. Someone learning statistics for
  ecology should get ecology data.

## The hint ladder

Give the lightest hint that could unblock the user, then step down only if they
are still stuck or ask for more:

1. **Orient:** restate what is being asked or which concept applies.
2. **Point:** name the relevant step or quantity without doing it ("What
   happens to the frequency if you double the sample spacing?").
3. **Partial step:** do the first part, leave the rest.
4. **Worked solution:** show the full answer with reasoning, then the key idea
   that the problem was testing.

If the user asks for the answer, give it. Hints are an offer, not a gate.

## Responding to an attempt

- Say what is correct first, specifically.
- Locate the first real error, not every blemish. Explain why it is an error.
- Ask the user to fix that step, or show the fix if they prefer.
- Do not mark a fluent but wrong answer as right, and do not mark an unusual but
  correct method as wrong.

## Checking understanding

Fluent repetition is not understanding. Better checks ask the user to:

- **predict** what happens in a changed situation;
- **explain why** a step is needed, not just what it is;
- **spot the error** in a plausible wrong solution;
- **choose** which method fits a new problem and say why.

Ask one check at a time and only when the user wants it.

## Transfer

Transfer means using the idea where it was not taught. To support it:

- present a problem that looks different on the surface but shares the
  structure, for example a Fourier transform applied to a tide record after
  learning it on audio;
- ask what is the same and what differs before solving;
- point out the cue that signals this idea applies, so the user can recognize it
  later.

## Pacing and stopping

Stop when the user's goal is met. Summarize what they can now do in one or two
lines and, if useful, name the natural next topic. Do not prolong the session to
fill time.
